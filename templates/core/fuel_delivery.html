    Recommended scale is bounded to 0.85–1.05 and applied only on request. Lower fuel use alone does not establish an optimum. “Fuel saving” uses the untrimmed corrected-fuel baseline; comparison below uses a fresh scale-1.00 run with fuel trims.

    Learning guide and model boundaries

    Lambda = actual air–fuel ratio / stoichiometric air–fuel ratio. Lambda 1 means stoichiometric; lower is rich and higher is lean. The reference reaction is 2 C₈H₁₈ + 25 O₂ → 16 CO₂ + 18 H₂O: hydrogen in the fuel combines with oxygen to form water.

    STFT is the immediate correction: measured lambda 1.05 against target 1.00 produces +6%, adding fuel. At 0.95 it produces −6%, removing fuel. LTFT learns slowly while closed loop is enabled. Disabling closed-loop control sets STFT to zero and stops new LTFT learning; it does not erase learned LTFT. Reset or Run new clears it.

    Calculated fuel delivery is theoretical even at injector saturation. Measured lambda, air flow, RPM and torque are independent inputs, not simulated feedback from a physical engine. Colour shows rich/lean relative to the selected target (±0.03); warnings separately check the 0.85–1.10 educational band.

    Equations and wiring inspected in the supplied Simulink file. The web model uses the supplied deterministic time-step method; no MATLAB numerical run was performed. The Simulink LTFT integrator precedes its output saturation, so its internal accumulation is retained. This is not a validated fuel-economy prediction or safe ECU calibration.

    JSON provides named outputs and the legacy eight-value vector. CSV retains inputs for each time sample. Exports are local learning evidence; no assessment is submitted, no private integration token is generated, and the model remains separate from Engine Live Data Demonstration.
