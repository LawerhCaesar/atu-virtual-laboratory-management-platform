3. WHAT THIS MODEL MEANS

This is a one-second, requested-speed system-energy comparison of a fuel-cell /
battery electric passenger van and a conventional diesel reference van. It uses
the same commanded driving cycle, grade and payload, with different vehicle masses.
The model assesses whether component limits support the requested operation.
It DOES NOT solve longitudinal dynamics to predict achieved vehicle speed.

The current default study uses a 120 kW electric motor, 120 kW diesel engine,
96s41p battery (59.51232 kWh nominal), 45 kW fuel-cell module, and 2 kg usable
hydrogen. Treat these as editable study assumptions. Preserve the actual parameters
from the catalog; do not reconstruct all values from this short description.

Keep these distinct in the UI and API:
  - Commanded speed and commanded distance versus demonstrated achievable motion.
  - Fuel-cell module output versus output after its boost-converter loss.
  - Battery stored-energy inventory versus nominal voltage times amp-hours.
  - Battery terminal power versus power on the regulated DC bus.
  - Accepted regenerative energy versus total requested braking energy.
  - Source energy versus electrical energy circulating within the powertrain.
  - Input price assumptions versus measured market prices.

Do not add measured-route, range-completion, emissions, tank-pressure, detailed
electrochemistry, switching-waveform, axle-load or structural-safety claims. They
require models or evidence not supplied here. Changing component ratings does not
automatically change vehicle mass: make the separate mass inputs visible.

4. CONVERSION METHOD AND EXECUTION ORDER

Implement a pure numerical package independent of React, the DOM and charting.
Use JavaScript Number / Float64 precision. Never round intermediate calculations.
Use explicit units at boundaries and descriptive internal names. Round only display
strings. The simulation clock remains a fixed 1 s; UI playback rate changes neither
the solver step nor the computed results.

First inventory every block type in native_model.json. Produce a conversion map
from original full block path and SID to the implementing module/function. Account
for every computational block. Display and Scope blocks become presentation and
logging; annotations and coordinates become documentation. Subsystems, Inports,
Outports and Mux blocks define hierarchy and vector order, not new equations.

Resolve From/Goto references by their exported tag visibility and subsystem scope.
Do not match similarly named tags globally. Resolve mask parameters in the correct
parent scope, including vector entries and derived constants. Inspect the exported
mask initialization code and preserve relevant calculations explicitly. Do not
evaluate arbitrary user expressions or execute MATLAB code in the browser.

Translate Fcn expressions using a tested parser or explicit generated functions.
Preserve one-based u(i) indexing, operator precedence, numeric true/false values,
and each function's semantics. MATLAB/Simulink ^ means exponentiation, not the
JavaScript XOR operator. Preserve guards and small denominator tolerances exactly;
changing them to generic clamps can change feasibility flags. Do not use eval or
new Function on values supplied by the user or imported scenarios.

This exact export has 23 block types, 302 Fcn blocks, 17 UnitDelay state blocks,
one DigitalClock and one one-dimensional Lookup_n-D block. There are no
DiscreteIntegrator blocks: integration is expressed through explicit arithmetic
and UnitDelay feedback. Port those recurrences as exported, not as newly invented
integrators. All 70 user-editable entries (52 operating/component constants and
18 battery-mask settings) are enumerated in the parameter catalog.

Construct an execution graph. Separate stateful blocks from direct-feedthrough
calculations, resolve dependencies and detect unresolved algebraic loops. Apply
each block's actual sample time, initialization, update method, saturation, reset
and output behavior. Preserve Unit Delay initial state and one-step latency. For
Forward Euler discrete integrators, expose the current state as this step's output
and compute the next state from this step's input; confirm the actual configured
initial-condition semantics. Do not update states opportunistically while walking
the graph. Emit the t=0 sample, then each second through the stop time inclusive.
The 3600 s reference run therefore has 3601 samples.

The current OCV Lookup_n-D block has one dimension, linear point-slope interpolation
and Clip extrapolation. Its dormant settings for higher dimensions are not active.
Check all Lookup Table breakpoint, interpolation and extrapolation settings. The
battery OCV curve and its integrated stored-energy inventory must remain consistent.
Respect the exact Switch criteria and threshold, Sum signs, Product multiplication
or division order, MinMax mode/port count, Saturation limits, RelationalOperator
and Logic output types, and gain expressions. Unsupported behavior must produce
an actionable error naming the original block, not a fabricated default result.

The 27 diagram systems may be reorganized into maintainable modules AFTER parity
is established. Keep these domain boundaries recognizable:
  parameters / drive cycle / road demand
  motor / inverter / energy management / fuel cell / hydrogen inventory
  boost converter / DC bus and braking / battery converter and power limits
  battery configuration / SOC and OCV / current limits / thermal behavior
  battery electrical losses and energy inventory

5. MODEL RULES THAT MUST SURVIVE THE CONVERSION

Copy exact behavior from the export, including boundary conditions. At minimum:
  - The built-in demonstration cycle repeats every 600 s. Its ramp, cruise,
    deceleration and stop portions must match the source, including transitions.
  - Battery current is positive for discharge and negative for charge. Preserve
    SOC-, temperature-, current- and voltage-based limits and coulombic efficiency.
  - Initial battery temperature differs from ambient temperature. Keep I^2 R
    heating and thermal transfer to ambient, with the configured initial state.
  - Fuel-cell control includes SOC hysteresis, enable state, hydrogen availability,
    ramp limits, converter loss and charging allowance. Protective reductions can
    differ from the normal upward ramp. Empty hydrogen must disable fuel production.
  - Diesel fuel includes idle and simplified overrun fuel cut, accessory load,
    rated power, engine efficiency and transmission/alternator losses.
  - Preserve each shortfall calculation and the cumulative feasibility conditions.
    Do not infer journey feasibility from the final instantaneous shortfall alone.

The exported comparison flag is specifically: commanded distance > 0.0001 km,
cumulative electric DC unmet energy < 0.000001 kWh, and cumulative diesel unmet
energy < 0.000001 kWh. It does not directly test motor shortfall or the mass screen.
Preserve that raw rule for parity, and show motor shortfall and mass excess as
separate limitations. Label the UI status 'Model comparison eligible', not a claim
of comprehensive vehicle feasibility. Never silently strengthen the native flag
while claiming an exact port. A broader eligibility rule needs a separately
versioned model change and new reference results.

Preserve the source-energy comparison without double counting:
  signed battery depletion = initial stored inventory - current stored inventory
  electric source energy = hydrogen used * hydrogen LHV + signed battery depletion
  diesel source energy = diesel litres used * diesel LHV
  energy saving (%) = 100 * (1 - electric source energy / diesel source energy)
  electric refill cost = hydrogen used * hydrogen price
      + max(battery depletion, 0) / grid-charge efficiency * electricity price
  diesel refill cost = diesel litres used * diesel price
  cost saving = diesel refill cost - electric refill cost

Apply the model's guards to these expressions. Fuel-cell electrical output and
gross battery discharge must not be added again as independent source energy.
Zero default prices mean not entered. Individual refill costs require all three
prices to be positive. The cost-saving comparison additionally requires the native
comparison flag and signed battery depletion >= -0.001 kWh. A larger final
battery-energy surplus receives no refill-cost credit and suppresses the model's
cost-saving comparison. Keep the 0.001 kWh tolerance. Source energy excludes upstream fuel production; costs
exclude vehicle purchase, maintenance and infrastructure.

Use validity flags, not the sign of a result, to distinguish unavailable values
from real negative savings. A numeric -1 is a raw-model sentinel when its relevant
validity flag is false; it can also be a real numeric saving when the flag is true.
Retain raw values in the engine/CSV. In the user interface use null plus a status
and a clear reason, such as 'Enter all three energy prices', 'Zero commanded
distance', 'Requested demand not fully supported', or 'Battery ended with a surplus'.
Trace each reason to the relevant source logic; do not replace model flags with
invented approximations.
